# Лабораторна робота № 3 — варіант 11

**Тема:** Нездатні до змін структури даних (immutability) у Python  
**Предметна область:** Навчальні курси

## Структура проєкту
- `model.py` — frozen dataclasses `Course`, `Module`, фабрика read-only налаштувань.
- `core.py` — чисті функції додавання модуля/тегу, зміни налаштувань і назви, вибірки курсів.
- `app.py`, `main.py` — демонстрація роботи через CLI.
- `tests/` — тести незмінності, read-only поведінки, хешованості та повторних оновлень.

## Реалізовані вимоги
1. Дві доменні сутності: `Course` і `Module`, обидві `@dataclass(frozen=True, slots=True)`.
2. `modules` зберігаються в `tuple`, `tags` — у `frozenset`.
3. `settings` створюються через `MappingProxyType(dict(kwargs))`, тобто джерело попередньо копіюється.
4. Pure updates повертають нові об'єкти: `add_module`, `add_tag`, `update_setting`, `rename_course`.
5. Pytest перевіряє відсутність мутацій, read-only налаштування та нові копії. `Module` є хешованим; `Course` не хешується, оскільки поле `settings` містить `MappingProxyType`, який не має хешу.
6. Час тестів можна порівнювати командою `pytest -q --durations=5`. Окремий тест повторює 100 immutable-оновлень.
7. Конфігурації mypy, black і ruff включено.

## Запуск
```bash
python -m pip install -r requirements.txt
python main.py
pytest -q --durations=5
mypy
black --check .
ruff check .
```

## Висновок
Незмінна модель курсу запобігає випадковим змінам стану: модулі зберігаються в кортежі, теги — у незмінній множині, а налаштування доступні лише для читання. Оновлення створюють нові екземпляри `Course`, тому початковий об'єкт залишається незмінним. Перевагами є передбачуваність і простіше тестування; накладні витрати — створення нових об'єктів і копіювання налаштувань під час оновлення.
